# The final two years are a locked Holdout, run once per Strategy version

Validation is Walk-Forward on the earlier history. The most recent two years are locked: a Strategy version runs on them exactly once, the result is written to the Ledger permanently, and running again requires a new Strategy version. Once a holdout has been looked at it is no longer out of sample; this rule makes that cost explicit and prevents the quiet iteration that turns a holdout into a training set.

## Amendment (2026-10-24, #72): the Protocol, the family, and the Fresh Period

Running the Holdout once is not enough if what is run on it was shaped by looking at it, or if the grid and the objective can be adjusted after the result is seen. So:

- **The Protocol is frozen before any run.** One append-only Ledger row, keyed by its content hash, states the parameter grid, the objective (in-sample Sharpe after costs, averaged with each cell's grid neighbours along every axis, so a lone spike loses to a plateau; a cell with fewer than 30 in-sample trades is ineligible), the tie-break order, the Window boundaries as trading days generated from the Trading Calendar and printed for independent checking, the cost and Slippage parameters, the exit band, the Participation Cap and the other Limits, the daily-loss and drawdown Halt fractions the report lists Halt days at (frozen since #84, so a report always reads the Protocol's, never the configuration's of the day), the starting Equity and risk-free rate, the Gate thresholds, the Universe Rule version and the data snapshot: the Universe build ids and hashes of every month in range, and the hash of the Adjusted Series of every ever-member over the Protocol's date range (ADR 0005 amendment). The row is keyed by the hash of its canonical serialisation (sorted keys, fixed decimals). The engine refuses a backtest naming no frozen Protocol, and before running recomputes both hashes and refuses if any differs. A Strategy version is its code revision run under one Protocol; a different grid or objective is a new version. The code revision is a hash over the parsed code of the `strategy` package's modules the Strategy imports, docstrings stripped, so a comment or formatting change does not bump it and a change in `queries` or `adjust` does not either. The Protocol records the git commit it was frozen at, and the engine refuses any run under that Protocol, a Window or the Holdout, at a different commit, so the Stitched Curve and the Holdout always share one engine. Neither a freeze nor a run is allowed from a working tree with uncommitted changes to tracked files, so changed code cannot pass as the commit it was changed from. An engine fix before the Holdout runs means a new Protocol at the new commit and a rerun of the Windows.
- **The Holdout is fixed, month-aligned, and never extended:** 2024-10-01 to 2026-09-30. Walk-Forward Windows are anchored back from it: five Out-of-Sample Windows in October-to-September years, 2019-10 to 2024-09, each with the two years before as its In-Sample Window. Positions keep their exits across Window boundaries; the Stitched Curve is one account. Every Position closes at the Holdout boundary (ADR 0003 amendment), and the Holdout starts the account again.
- **The Holdout is consumed for the whole Strategy Family.** Family membership is recorded at freeze, so relabelling a version as a new family to reset the lock is visible in the lineage the Gate report shows. For a single Operator, visibility is enough; no rule polices what counts as a rule shape.
- **A later version's Holdout run is Not Independent**, recorded as such, and passes the Backtest Gate only together with a Fresh Period: trading days after both the consumed Holdout's end and that version's own Protocol freeze. Data from October 2026 onward is not untouched just because no backtest ran on it; the Operator watches the market and the first version's paper results and can shape the next version around them, so only days after its freeze are data its design could not have used. The Fresh Period must be at least twelve months long and meet the same thresholds, its trade count reported but not required. This is cheaper and repeatable beside paper trading alone, and does not freeze the family for two years. It also sets the cadence: a later version waits a year after its freeze before it can pass. `tradeline backtest fresh --protocol P` runs it: the parameters the version's Holdout ran at, in a fresh account at the Protocol's starting Equity, over the Fresh Period's trading days to the last day with data, recorded in the Ledger (`fresh_periods`, its Runs under their own backtest id) and extended as data arrives. The engine allows days after the Protocol's Holdout for this alone, and the Protocol's data snapshot cannot cover them. The Backtest Gate scores the account once it has run twelve months.
- **A second Holdout run by the same version is refused** by the engine and recorded in the Ledger as an attempt. A rerun on any seen period after a data correction, one whose Universe or Adjusted Series hash differs from the one the earlier run verified, is Not Independent under any version.
- **The Backtest Gate scores both** the Stitched Curve and the Holdout (`docs/risk-controls.md`, Gates); either failing fails.
- **The c sensitivity is information, never a run of the Holdout.** The report's reruns of the Holdout with the Slippage impact c at zero and at twice its value, at the parameters the Holdout ran at, each in its own account, neither consume the family's Holdout nor count as an attempt: they are recorded apart (`cost_sensitivities`), every Run of them states the c it was priced with, and the Gate never reads them.

Alternatives rejected: letting a later version advance only by the Paper Gate (slower and not repeatable); declaring a new two-year Holdout when enough data exists (freezes the family for two years); counting the Fresh Period from the consumed Holdout's end alone (the Operator has seen those days).

## Amendment (2026-10-24, #85): a frozen commit stays reachable

A Protocol names the git commit it was frozen at, and a run under it is refused at any other commit, so a Protocol whose commit is lost can never be run or checked again. Every Protocol that ran a Walk-Forward, a Holdout or a reproduction is tagged `protocol/<first 12 characters of its hash>` at its commit, and a branch carrying one merges with a merge commit, never squashed or rebased. A Protocol is run from a checkout nothing else touches while it runs: the engine checks the commit and the clean tree at each cell's start, not during it (#87).

## Amendment (2026-10-25, Phase 2b): a first version can be Not Independent, the Drift Replay, and Machinery Corrections

The `lowvol` family has never run on the Holdout, but it was chosen after reading published results (NSE's factor indices among them) that cover the Holdout's years. So:

- **A first version is Not Independent when its family was chosen after reading published results covering the Holdout's years.** It is recorded so at freeze, with that reason. `lowvol_v1` is. Its Holdout still runs once and is recorded, and it passes the Backtest Gate only with a Fresh Period.
- **The Fresh Period is a backtest.** It runs at the frozen Protocol's commit, with its data-snapshot checks, over the trading days after both the Holdout's end and the freeze, and needs nothing from Phase 3. Its account starts with an Initial Buy on its first trading day, as the Holdout's and paper's do: entrants chosen as at a Rebalance from data through the previous close and bought that day. For a portfolio Strategy it needs at least two scheduled Rebalances after the Initial Buy as well as twelve months; the Initial Buy is not a Rebalance and does not count. From a freeze around November 2026 the earliest pass is about November 2027.
- **A portfolio Strategy's grid may be one cell.** `lowvol` has no free parameter, so Walk-Forward selects nothing and the Stitched Curve is one continuous backtest over the Out-of-Sample years; the Protocol says so rather than inventing parameters to tune.
- **The Drift Replay is the one run under a Protocol allowed at another commit.** It reruns the Out-of-Sample Windows and any Fresh Period days at a later commit and compares holdings, Fills, costs, dividends and the tax ledger with the runs at the frozen commit. It never runs the Holdout, is recorded apart in its own table, never counts as a Window run, and is never read by a Gate. It runs for every new commit, cached by commit, and a paper Run refuses to start at a commit without a pass. A difference only in ids, timestamps or formatting can be explained. A difference in money means the change is reverted, or a new version is frozen.
- **A change in money resets the Fresh Period unless it is a Machinery Correction.** A new version is Not Independent and its Fresh Period starts at its own freeze. A Machinery Correction keeps the Fresh Period running, and needs all three: the Strategy version hash is unchanged; the bug was shown first by a failing test against a record outside the system's own results (a contract note, NSE's rows, a corporate-action filing, a broker statement, a published tax rule); and the old and new results on the Stitched Curve and the Fresh Period days so far are reported together. It is frozen as a new Protocol at the fixed commit, recording the correction and its evidence. A change justified by judgement or by results, or one touching the Strategy, is not one. The line is the one drawn for #85's rounding fix: whether outcomes could have informed the change.
- **After a Machinery Correction the Holdout's result stands as recorded,** and the Gate reads it. The report marks it computed before the correction, puts the correction's measured effect on the Stitched Curve (in annualised excess and drawdown) beside it, and flags the Holdout outcome as sensitive to that correction when its margin against any gated threshold is smaller than that effect. The flag is a comparison of two measured numbers, never a threshold.
- **The machinery is checked before the Holdout runs.** The acceptance run refuses to start the Holdout until the contract-note test has passed or is explicitly accepted as unmet; every dividend subject of every Universe member that was eligible at a decision date in the Stitched and Holdout years has parsed or is listed with a reason; the demerger table has been checked against NSE's Corporate Action list for those members and years; and the tax ledger's synthetic tests pass. Each is checked from records, not results, and a bug found then is fixed while a fix is free.
- **Data after the freeze is checked weekly.** The Integrity Check runs on post-freeze data each week and alerts on a gap. The Raw Series and Corporate Actions can be fetched from NSE's archive years later, so a gap is not lost evidence; it is cheap to fix within a week and expensive when it surfaces at the Fresh Period run as a refetch and a rebuilt Universe. A missing Kite candle is reported as a Kite Parity gap only.

Each fix that changes money still costs at least a correction, a re-freeze and a published comparison, and one that is not a Machinery Correction costs up to a year. Phase 3 is built conservatively for that reason, with the Drift Replay run before a merge, not after.

Alternatives rejected: a new status for a partly independent Holdout, reported but not gated (the Fresh Period already exists for this); an equality-only replay of the Holdout for the drift check (a hole the Holdout's performance could later be read through); a single drift check before paper starts (stale with the next merge); freezing the whole engine at the Protocol's commit for paper (Phase 3 could then fix nothing); resetting the Fresh Period on every change in money (a rule too costly to obey gets worked around); after a correction, dropping the Holdout from the Gate (rewards finding a correction after a failing Holdout) or a size threshold on the correction (arbitrary).
